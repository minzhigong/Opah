# Opah 部署文档

本文档介绍 Opah 的两种运行形态：**Windows 本机运行（主用）**与 **Linux 服务器 Compose 部署**。Opah 由以下部分组成：

| 组件 | 说明 | 端口 |
| --- | --- | --- |
| opah-server | Spring Boot 后端（REST API + SSH + Docker 操作） | 8787（仅主机暴露） |
| web | React 前端静态资源（Vite + Ant Design） | 由静态服务器/Nginx 提供 |

镜像分发不依赖任何 Registry：构建机 `docker save` 导出，经 SSH 管道直达目标主机 `docker load`。

## 1. 环境要求

**Windows 本机运行（主用）**：

- JDK 17+、Maven 3.9+（或直接使用发布 jar 免 Maven）
- Docker Desktop 已启动（Linux 容器模式），Opah 默认经 named pipe `npipe:////./pipe/docker_engine` 连接，可用 `DOCKER_HOST` 覆盖

**Linux 服务器 Compose**：

- Docker Engine 24+ 及 Docker Compose v2
- 宿主机需有 `/var/run/docker.sock`（Opah 通过它构建镜像、管理容器）
- 构建前端需要 Node 18+（如只在服务器上运行后端可跳过）
- 服务器建议配置：2 核 / 4GB 内存 / 50GB 磁盘（构建镜像与导出产物会占用空间）

## 2. Linux 快速部署（Docker Compose）

方式一：一键脚本（单文件即可部署，自动拉取 Git 代码、生成密钥、构建前端、启动服务、健康检查）：

```bash
# 下载单文件脚本到任意目录直接运行（默认拉取 main 分支到 /opt/opah）
curl -fsSL https://raw.githubusercontent.com/minzhigong/Opah/main/deploy.sh -o deploy.sh && chmod +x deploy.sh
./deploy.sh                                   # 部署 / 升级
./deploy.sh --with-nginx                      # 同时安装 Nginx 前端配置
REPO_URL=git@... BRANCH=dev INSTALL_DIR=/data/opah ./deploy.sh   # 覆盖默认仓库/分支/目录
```

方式二：手动执行以下步骤：

```bash
# 1. 获取代码
git clone <仓库地址> opah && cd opah

# 2. 配置环境变量（生产必改）
cat > .env <<'EOF'
OPAH_SECRET_KEY=<随机生成，例如：openssl rand -hex 32>
OPAH_ADMIN_PASSWORD=<管理员密码>
EOF

# 3. 构建并启动（opah-server）
docker compose up -d --build

# 4. 确认状态
docker compose ps          # opah-server 应为 running
docker compose logs -f opah-server
```

启动后后端监听 `http://<服务器IP>:8787`（可用环境变量 `OPAH_PORT` 修改宿主机映射端口）。

### 2.1 环境变量说明

| 变量 | 说明 | 默认值 |
| --- | --- | --- |
| `OPAH_SECRET_KEY` | 凭据加密主密钥，**生产必须修改**，丢失后已加密凭据无法解密 | change-me-in-production |
| `OPAH_ADMIN_PASSWORD` | 初始管理员（admin）密码 | opah-admin |
| `OPAH_DATA_DIR` | 数据目录（SQLite 数据库、配置等），容器内默认 `/data/opah` | /data/opah |

### 2.2 数据持久化

- `opah-data` 卷：SQLite 数据库与 Opah 自身数据（挂在容器 `/data/opah`）

备份示例：

```bash
docker run --rm -v opah-data:/data -v $(pwd):/backup alpine \
  tar czf /backup/opah-data-$(date +%F).tar.gz -C /data .
```

## 3. 前端部署

前端为纯静态产物，构建后由任意静态服务器提供，并将 `/api` 反向代理到后端。

```bash
cd web
npm install
npm run build        # 产物在 web/dist
```

Nginx 配置示例：

```nginx
server {
    listen 80;
    server_name opah.example.com;

    root /var/www/opah/dist;
    index index.html;

    location /api/ {
        proxy_pass http://127.0.0.1:8787;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    location / {
        try_files $uri $uri/ /index.html;
    }
}
```

建议同时配置 HTTPS（certbot 或自备证书），因为登录会话依赖 Cookie。

## 4. Windows 本机运行（主用形态）

```powershell
# 前置：Docker Desktop 已启动；JDK 17+ 与 Maven 已安装
cd server
mvn spring-boot:run
# 或打包后运行
mvn package -DskipTests
java -jar target/opah-server-0.1.0-SNAPSHOT.jar
```

- 数据目录默认 `server/data`（可用 `OPAH_DATA_DIR` 指定其他位置）
- Docker 连接默认走 `npipe:////./pipe/docker_engine`，可用 `DOCKER_HOST` 环境变量覆盖（如 `tcp://localhost:2375`，需在 Docker Desktop 开启 TCP 暴露）
- 连通性验证（登录后）：

```bash
curl -b cookies.txt http://localhost:8787/api/v1/system/docker
# 期望 {"connected":true,...,"osType":"linux"}
```

前端开发模式：`cd web && npm install && npm run dev`（`/api` 代理到 8787）。

## 5. 升级

```bash
git pull
docker compose up -d --build     # 数据库迁移由 Flyway 在启动时自动执行
```

升级前建议先备份 `opah-data` 卷。

> **v0.2 存量升级提示**：若此前部署过含内置 Registry 的版本，升级后可清理不再使用的组件：
> `docker compose down && docker volume rm opah-registry`（如需保留旧镜像数据请先自行导出备份）。

## 6. 安全清单

- [ ] 修改 `OPAH_SECRET_KEY` 与 `OPAH_ADMIN_PASSWORD`
- [ ] 前端入口启用 HTTPS
- [ ] 8787 端口仅对内网 / Nginx 所在主机开放（`iptables` 或云安全组），避免绕过前端直连 API
- [ ] 定期备份 `opah-data` 卷

## 7. 常见问题

**Q: 容器启动报 `Cannot connect to the Docker daemon`？**
A: 确认已按 compose 文件挂载 `/var/run/docker.sock`，且宿主机 Docker 正常运行。

**Q: Windows 下启动日志提示 Docker 不可用 / `Cannot connect to the Docker daemon`？**
A: 确认 Docker Desktop 已启动且为 Linux 容器模式；调用 `/api/v1/system/docker` 查看 `error` 字段定位原因；必要时设置 `DOCKER_HOST=tcp://localhost:2375`（需在 Docker Desktop 设置中开启 TCP 暴露）。

**Q: 忘记 `OPAH_SECRET_KEY` 会怎样？**
A: 已保存的 SSH 等凭据无法解密，需重新录入。该密钥一经使用请妥善保管。

**Q: 如何重置管理员密码？**
A: 首次启动前通过 `OPAH_ADMIN_PASSWORD` 设置；若已初始化，需在应用内修改，或删除数据卷后重新初始化（会丢失所有数据）。
